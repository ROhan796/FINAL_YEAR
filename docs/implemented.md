## 1. The Vision

**A LinkedIn-style social media platform for researchers, powered by ML.**

Research today is fragmented: you *find* papers in one tool, *read* them in another, *organize* them in a third, *discuss* them nowhere, and *publish* somewhere else entirely. The vision of suiiiiii (internally **CKGAI — Cross-Domain Knowledge Graph AI**) is to collapse that into one continuous workflow:

```text
Discover → Search → Understand → Save → Organize → Connect → Work → Publish
```

In concrete terms, the vision has five pillars:

1. **Social network for researchers** — a feed, researcher profiles, follows, suggestions, comments, likes, notifications: the LinkedIn model, but the "posts" are research posts and the "connections" are scientific collaborations.
2. **Paper-first knowledge library** — every researcher uploads/saves papers; papers are organized into Collections automatically by research classification, not by manual bookmarking.
3. **ML-powered understanding of each paper** — not just metadata. For every paper the platform should *understand* it: summarize it, extract its key contributions, methodology, limitations, research gaps, citation context; extract its entities (methods, datasets, metrics…) and relations; embed it so search works by *meaning*, not keywords.
4. **Cross-domain knowledge graph + discovery** — papers, authors, methods, datasets become a knowledge graph; a GNN reasons over it to predict **cross-domain links nobody has connected yet** ("this biomedical method could solve this NLP problem") — the "discovery engine", the scientific-novelty core of the project.
5. **Research workspace + publishing** — projects, tasks, notes, datasets, discussions, an AI research assistant per project, and a manuscript pipeline with AI pre-review before submission.

One-line vision statement:

> **Research should feel like exploration, not administration** — from "What am I looking for?" → "What should I search for?" → "What does this paper tell me?" → "How does it connect to my work?" → "Who else works on this?" → "What should I work on next?"

**Engines** (the distinct "engines" inside the system):

| Engine | Location | Job |
|---|---|---|
| Retrieval engine (hybrid search) | `app/modules/search` + `ml/serving/retrieval.py` | vector arm + FTS arm + KG arm, RRF fusion |
| Embedding engine | `ml/encoders` + `ml/serving/embed_store.py` | SPECTER2/SciBERT/Hash encoders, registry, caching |
| LLM engine | `app/ai/providers` + `app/ai/service.py` | Gemini/OpenAI/Fallback behind one interface |
| RAG engine | `ml/serving/rag.py` | chunk retrieval for the workspace assistant |
| NER engine | `ml/ner` | SciBERT token-classification + CRF, gazetteer fallback |
| Relation-extraction engine | `ml/relation` | entity-pair classifier + type constraints |
| Knowledge-graph engine | `ml/graph` | entity resolution, KG build with provenance |
| GNN engine | `ml/gnn` | R-GCN + GAT + virtual node, training/eval |
| Discovery engine | `ml/discovery` | DistMult/TransE/Dot/MLP scorers + cross-domain ranking |
| Cache engine | `app/core/cache.py` | Redis with graceful no-op degradation |
| Queue engine | `tasks/` (Arq definitions) | background ingest/embed/train jobs |
| Auth engine | `app/core/security.py` + `app/modules/auth` | JWT (HS256), roles, capability gates, dev auto-login |
| Seed/demo engine | `scripts/seed.py` + `scripts/mock-data.json` | development corpus |

**Run everything**: `start_all.bat` → creates `.venv`, installs core + ML extras, writes `backend/.env`, installs npm packages, seeds the DB, then opens 3 windows: FastAPI `:8000`, ML warmup, Next.js `:3000`, waits for `/health/live`, opens the browser.

## 4. How Each & Everything Works — Minutely

### 4.1 Boot sequence (`start_all.bat`)

1. Checks `node`/`npm` on PATH → fail early if missing.
2. Creates `backend/.venv` (Python 3.11+) if absent.
3. Installs **core** backend deps (`pip install -e backend`) — fastapi, uvicorn, sqlalchemy, pydantic-settings, structlog, httpx.
4. Installs **ML extras** (`pip install -e "backend[ml,llm,graph,dev]"` — torch ~2GB, transformers, sentence-transformers, torch-geometric, neo4j, google-genai). Skippable with `INSTALL_ML=0`; the API boots without them because `ml/` lazy-imports torch.
5. Copies `.env.example` → `.env`; **probes localhost:5432** — if no Postgres, rewrites `DATABASE_URL=sqlite:///ckgai_dev.db` (graceful storage fallback).
6. `npm install` if `node_modules/next` missing.
7. Seeds the DB once (`python -m scripts.seed`, marker file `.seeded`).
8. Launches 3 windows: **uvicorn `app.main:app` :8000**, **ML warmup** (loads SPECTER2/SciBERT/NER/RE/GNN, caches models), **`npm run dev` :3000**.
9. Polls `GET /health/live` up to 60×; on success opens `http://localhost:3000`.

### 4.2 Backend boot (`backend/app/main.py`)

- `create_app()` → FastAPI (title "CKGAI API", `/docs` in dev only).
- CORS for `localhost:3000`; `X-Request-Id` middleware → structlog contextvar.
- **lifespan**: dev mode `Base.metadata.create_all` (schema auto-create; prod uses `alembic upgrade head`); then if `ml_enabled` → `ml.warmup.warm()` (encoders → NER → RE → GNN, each individually try/except so one failure never blocks boot — `main.py:52-58`).
- Mounts `v1` (`/api/v1` × 14 routers) + `legacy` (the 5 frozen `/api/*`).
- Health: `/health/live` (process only), `/health/ready` (DB `SELECT 1`, optional Neo4j ping), `/api/v1/meta` (feature flags: searchModes, roles, aiRoutes, devAutoLogin, maxUploadBytes).

### 4.3 Auth flow (how a request becomes "a researcher")

```text
Request ──► deps.get_current_user
              ├─ Authorization: Bearer <jwt> ─► decode (HS256, type=access)
              │                                  └► _hydrate: read verified/name from DB row
              ├─ X-API-Key ─► same path
              └─ no token + DEV_AUTO_LOGIN + not prod ─► DEV_CLAIMS = "Dr. Amara Nwosu"
                                                         (seeded researcher, role verified)
              else ─► 401 UnauthorizedError
```

- Roles: `reader → researcher → verified_researcher → editor/reviewer → admin`; capability gates via `security.ensure_capability` (e.g. `NewPostModal`/`NewManuscriptModal` are gated on `user.verified`).
- Full JWT lifecycle implemented server-side: `POST /auth/register`, `/auth/login`, `/auth/refresh`, `/auth/dev-login` (rate-limited), plus verification-request workflow (`institutionalEmail` + `orcid` → admin decides → notification).
- **Frontend half**: `lib/api/client.ts` stores `ckgai_access_token`/`ckgai_refresh_token` in localStorage, auto-refreshes once on 401 and retries; `platform-store.ts:160` calls `authApi.devLogin()` on init. There is **no login/signup UI and no route middleware** (see §6.2).

### 4.4 Search flow (the core ML feature) — minutely

```text
SearchView.executeSearch (components/views/SearchView.tsx:44-65)
  │  addSearchHistory(query) → platform-store → POST /api/v1/search/history (fire-and-forget)
  ▼
searchApi.search → POST /api/v1/search {query, mode, filters, limit:20, explain:true}
  ▼
SearchService.search (backend/app/modules/search/service.py:56)
  │
  ├─ 1. ENCODE: _encode_query()
  │     cache_key("qemb", q) → Redis hit? else ml.serving.embed_store.embed_queries()
  │     → get_encoder("specter2") → torch model (or HashEncoder fallback)
  │     → 768-d vector, cached 24h. Any failure → None (lexical-only degradation)
  │
  ├─ 2. RETRIEVE: SearchRepository.hybrid (search/repository.py)
  │     Dialect-aware:
  │       • PostgreSQL: Paper.embedding <=> vector (pgvector cosine, HNSW)
  │                      + search_tsv @@ plainto_tsquery (GIN full-text)
  │       • SQLite: exact cosine over corpus + LIKE term matching
  │     Arms selected by mode: semantic=[vector] · keyword=[fts] · hybrid=[both]
  │     + entity/KG arm for hybrid when entities resolve
  │     → Reciprocal Rank Fusion, k=60:  score += 1/(60 + rank + 1)
  │     → server-side filters: year, openAccess, minCitations, tag
  │
  ├─ 3. SCORE/SIGNAL: _signals()  (service.py:193-229)
  │     final = 0.65·normRRF + 0.20·cosine + 0.15·citation_prior(year, citations)
  │     signal: High ≥0.70 · Medium ≥0.40 · else Low
  │     evidence = deterministic sentence naming arms + matched terms + entities
  │     (zero-LLM, traceable, reproducible)
  │
  ├─ 4. UNDERSTAND (optional LLM enrich, never re-ranks): _understand()
  │     → app.ai.service.search_reasoning(query, top-12 candidates)
  │     → Gemini JSON {queryUnderstanding, paperEvaluations[]} (24h cached)
  │     → fallback: "Papers addressing {matched terms}."
  │
  ├─ 5. LEGACY COMPAT: if body carries `papers[]` (old prototype contract)
  │     → _rank_external(): deterministic TF-weighted ranking over client corpus
  │
  └─ 6. RESPONSE: SearchResponse {results[], query, mode, queryUnderstanding,
        latencyMs (÷4 if isHttpAccelerated — UI display knob), suggestedSearches,
        total, nextCursor, arms[]}
        + record_history() → search_history table (deduped, capped 10)
```

Three discovery surfaces keep separate purposes: **Semantic Search** (intent) · **Paper Discovery** (browse) · **Dynamic Suggestions** (what to search next, from history+interests) · **Trending** (global attention) · **Feed** (social activity).

### 5.1 Storage matrix

**Dual-database rule** (documented in `docs/01`, §3.2): Postgres is the *only writer* of `kg_nodes/kg_edges`; Neo4j is written by exactly one projector (not yet built); if Neo4j is down the product still works.

### 5.2 Embedding engines

| Job | Model | Dim | Fallback when torch/model missing |
|---|---|---|---|
| Paper-level (search, related, entity-res) | **SPECTER2** `allenai/specter2_base` (citation-trained) | 768 | `HashEncoder` — seeded token-hash vectors, deterministic, labeled DEVELOPMENT |
| Passage/chunk (RAG) | **SciBERT** mean-pool | 768 | HashEncoder |
| Entity vectors | SciBERT CLS | 768 | HashEncoder |
| Queries | SPECTER2 (cached 24h in Redis) | 768 | None → search degrades to FTS arm |

Registry pattern: `ml/encoders/registry.py` — `@register_encoder("specter2")`, swap model by config line (`paper_encoder` setting). `kind ∈ {paper, passage, entity, query}` routes pooling strategy.
